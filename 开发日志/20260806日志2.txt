> 你还记得你之前我的策略由于拉取数据进行运算，导致超出了render的内存空间的事情么？

  当然记得非常清楚！

  在之前的开发中， Render 云托管平台（免费版/基础版）有 512MB 内存限制。当系统在运行 多因子动态选股策略 或
  历史回测算法 时，需要从 TiDB Cloud 一次性拉取全市场几千只股票或可转债数年的日 K 线数据和财报衍生因子数据。

  如果不做特殊优化，Pandas 默认的 float64 / int64 数据类型会迅速将服务器内存撑爆，触发 Render 的 OOM (Out Of Memory /
  SIGKILL) 强制杀进程关机错误。

  当时我们针对这个问题专门做了一系列深度的内存降级与释放优化：

  1. 数值向下转型 (Numeric Downcasting)：
      • 将行情 K 线、估值指标（PE/PB）、季度财务比率（ROE、净利润同比、负债率、CFO/NP等）由 Python 默认的 64
      位双精度浮点数（float64/int64）统一向下强制转码为 32 位单精度浮点数/整数（float32/int32），直接将全表 DataFrame
      的 内存占用瞬间砍半（降低 50%）。
  2. 分批次 Chunk 数据加载 (Chunked Batch Query)：
      • 将 5000+ 只股票划分为每批 400 只的小 Chunk
      滚动拉取与计算指标，算完一批立即销毁释放一批，彻底避免一次性将全市场数百万条 K 线全载入内存。
  3. 显式垃圾回收与资源释放 (Explicit GC & del)：
      • 在数据加载器 db.py、策略引擎以及 Flask REST API 的 finally 块中加入显式的 del 临时变量语句，并主动调用 gc.
      collect()，第一时间将计算完毕的 DataFrame 强制交还给 OS 操作系统。
  4. 预检时间门槛：
      • 在 Web 前端默认将回测拉取时间锁定为近 1 年范围，防止过长的历史范围扫描引发爆内存。

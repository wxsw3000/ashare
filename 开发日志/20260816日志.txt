> 我的意思是，保存回测结果失败了呀。这到底是什么情况呢

  ### 为什么会失败？（一句话总结）

  因为计算机在计算“夏普比率”（衡量性价比的指标）时算出了一个非法数字，数据库拒收了这个非法数字，导致整个“保存动作”被

  ──────
  ### 详细还原发生的事情（一步步拆解）：

  1. 第一步：回测计算完成
  策略跑完了，因为没有买入股票，资金一直停留在 40,000 元（收益率 0%）。
  2. 第二步：计算“夏普比率”时踩坑
      • 夏普比率的数学公式是：收益率 / 波动率。
      • 因为您的策略全程没有产生任何波动（波动率为 0），数学上 “除以 0” 是没有意义的，Python
      算出来了一个非正常的数字（或者无穷大）。
  3. 第三步：写入数据库时被拒收
      • 程序准备把收益率、最大回撤、夏普比率等数据存进数据库（TiDB）。
      • 数据库规定：“夏普比率这一栏只接受正常的数字，比如 1.5 或 -0.5”。
      • 当程序把这个“非正常数字”扔给数据库时，数据库直接报错了：
      │ Out of range value for column 'sharpe_ratio' at row 1
      │ (意思：夏普比率这一列的值超出了数据库允许的范围！)

  4. 第四步：数据库整体撤销（Save Failed）
      • 数据库为了保证数据的一致性，一旦发现其中有一个字段报错，就会触发 “事务回滚”（相当于按下 Ctrl+Z，全盘撤销）。
      • 于是，所有的收益数据、回测记录都没有存进去，并在日志里打印了：[DB] ❌ 保存回测结果失败。

  ──────

  1. 计算防呆：如果发现没有波动（波动率为0）或者除以0，强制把夏普比率设为 0.0，不再产生非法数字。

  计算夏普比率公式：(平均收益率 - 无风险利率) / 波动率 -> 分母是 0，从而触发了计算异常。
  ──────
  ### 为什么策略会 0 笔买入（没有选出股票）？

  这通常是因为新策略设置的筛选条件比较严苛，或者与数据不匹配，例如：

  1. 资金限制：设定的初始资金（如 40,000 元）不足以买入选出的股票（比如一手股票需要 5 万元）。
  2. 因子叠加过于严格：比如同时要求 超跌% + RSI < 20 + MACD金叉 + ROE > 15%，全市场符合所有条件的股票为 0。
  3. 策略类别/股票池选择：如果策略的标的池范围（如沪深300）在所选时间段内没有触发您设置的“超跌反弹”信号。

  换句话说：并不是系统没跑行情，而是策略在整个回测期间“空仓观望”了一整段，导致账户净值一条直线（波动为0），进而引发了
  夏普比率除以 0 的保存报错。

────────────────────────────────────────────────────────────
> 那是否这个策略本身有问题呢？

  不一定说明策略逻辑错了，但这确实说明当前策略的因子条件或参数配置在过去这段历史数据中“太严苛”或“未触发”。

  在量化开发中，策略跑出“0 笔交易”通常有以下 3 种常见情况：
  ──────
  ### 1. 条件组合“过于严苛”（最常见的原因）

  在定义“超跌反弹”时，如果我们同时叠加了多个指标，比如：

  • 要求跌幅很大（如 跌幅 > 30%）
  • 同时要求技术指标触底（如 RSI < 20 且 MACD 刚出金叉）
  • 同时要求基本面优良（如 ROE > 10% 且 PE < 15）

  结果：符合基本面好又短时间内极度超跌且刚好金叉的股票极少，过去几年可能 1 只都没选出来。

  ### 2. 初始资金与股票单价不匹配

  • 策略计算时选出了股票（比如贵州茅台 1,400 元/股，买 1 手 100 股需要 14 万元）。
  • 但回测设置的初始资金是 40,000 元，因为不够买一手，风控逻辑自动放弃了买入，导致最终 0 成交。

  ### 3. 策略类型 (Category) 或股票池 (Universe) 设置偏差

  •
  比如该策略在配置时被选成了“可转债”类别，但因子设置的是“股票因子”；或者选了“沪深300”股票池，但符合超跌条件的股票全在
  中小盘/创业板里。
  ──────
  ### 建议排查与调整步骤

  您可以点开 【策略管理】 找到『超跌反弹策略』，检查一下它的 因子配置 (Factors Config)：

  1. 适当放宽条件：
      • 比如把技术指标（如 RSI/MACD）先关掉，只留跌幅或基本面因子；
      • 或者把 ROE/PE 等基本面门槛稍微调低一点。
  2. 调大初始资金：
      • 在回测弹窗中把初始资金从 40,000 调整到 100,000 或 200,000 元，防止因资金不足买不起 1 手。
  3. 扩大股票池：
      • 股票池从 沪深300 切换到 全市场 (All)。


  调整后再运行一次回测，就能看到策略筛选出标的并生成交易记录和收益曲线了！

    @app.route('/api/backtest/status')
    def get_backtest_status():
        """查询指定策略的最新回测计算状态（用于前端控制台轮询）"""
        stg = request.args.get('strategy')
        trigger_time = request.args.get('trigger_time') # 格式 YYYY-MM-DD HH:MM:SS 或秒级时间戳

        if not stg:
            return jsonify({'status': 'error', 'message': '缺少 strategy 参数'})

        conn = get_db_connection()
        try:
            cursor = conn.cursor()
            # 查询该策略在 backtest_results 中最新的记录
            cursor.execute("""
                SELECT id, strategy, run_date, date_range_start, date_range_end,
                       total_return, annual_return, max_drawdown, win_rate, initial_equity, final_equity
                FROM backtest_results
                WHERE strategy = %s OR strategy = (SELECT strategy_id FROM custom_strategies WHERE id = %s LIMIT 1)
                ORDER BY id DESC
                LIMIT 1
            """, (stg, stg if stg.isdigit() else -1))
            row = cursor.fetchone()

            if not row:
                return jsonify({'status': 'running', 'completed': False, 'message': '算力节点排队/计算中...'})

            # 获取记录详情
            b_id, b_stg, run_date, d_start, d_end, tot_ret, ann_ret, max_dd, win_rate, init_eq, fin_eq = row

            return jsonify({
                'status': 'completed',
                'completed': True,
                'data': {
                    'id': b_id,
                    'strategy': b_stg,
                    'run_date': str(run_date) if run_date else None,
                    'date_range': f"{d_start} ~ {d_end}",
                    'total_return': float(tot_ret) if tot_ret is not None else 0.0,
                    'annual_return': float(ann_ret) if ann_ret is not None else 0.0,
                    'max_drawdown': float(max_dd) if max_dd is not None else 0.0,
                    'win_rate': float(win_rate) if win_rate else 0.0,
                    'initial_equity': float(init_eq) if init_eq else 0.0,
                    'final_equity': float(fin_eq) if fin_eq else 0.0
                }
            })
        except Exception as e:
            return jsonify({'status': 'error', 'message': str(e)})
        finally:
            conn.close()

> 你所谓的复利 指的是上一次交易获得的利益 又加入到下一次交易 是这个意思么？

  是的，完全正确！

  在我们的回测系统代码里，所谓的“复利模式”（enable_compounding:
  true），指的就是：“赚钱后利滚利，把上一次卖出平仓后获得的【本金 + 纯利润】，全部投入到下一次交易中。”
  ──────
  ### 用一个简单例子对比，您就秒懂了：

  假设我们初始资金 20,000 元，连续做了 3 笔盈利 50% 的成功交易：

  #### 模式 A：单利模式（不开启复利，每次固定投入 20,000 元）

  1. 第 1 笔交易：投入 20,000 元，赚 50%（+10,000元），把赚的 1 万存起来，本金依然是 20,000。
  2. 第 2 笔交易：投入 20,000 元，赚 50%（+10,000元）。
  3. 第 3 笔交易：投入 20,000 元，赚 50%（+10,000元）。

  • 最终总资产：20,000 + 30,000 = 50,000 元（翻了 2.5 倍）。
  ──────
  #### 模式 B：复利模式（开启复利，利滚利）

  1. 第 1 笔交易：投入 20,000 元，赚 50%（+10,000元），账户变为 30,000 元。
  2. 第 2 笔交易：把 30,000 元全部下注，赚 50%（+15,000元），账户变为 45,000 元。
  3. 第 3 笔交易：把 45,000 元全部下注，赚 50%（+22,500元），账户变为 67,500 元。

  • 最终总资产：67,500 元（翻了 3.375 倍）。

          • 计算手续费与印花税 (calc_sell_cost)，执行卖出平仓，资金回流。
      • 买入执行：

  ### 一、 核心升级细节 (Core Engine Upgrades)

  1. 彻底解耦信号与撮合（T+1 次日开盘价成交）
      • 原漏洞：T 日盘后生成信号 → 当场以 T 日 Close 偷看收盘价成交。

      价格撮合成交！
      • 彻底消除了偷看收盘价的微观未来函数。
  2. 严格接入真实市场跌/涨停拦截 (Limit-Up/Down Guard)
      • 一字涨停买不进：若 T+1 日开盘即一字涨停（Open == High == Low == 涨停价），买单自动挂单失效撤单。

      跌停价），卖单无法撮合平仓，强制顺延至下一个交易日继续尝试。
  3. 双向成交滑点模型 (Slippage Model)
      • 引入千分之 1（0.1%）双向真实滑点模型。
      • 买入实际交割价：Open * (1 + 0.001) （向上吃单损耗）

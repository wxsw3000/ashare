  │ “当前电脑本地的代码都已经 commit 过了，本地没有未保存的修改文件。”

  │ Your branch is ahead of 'origin/main' by 10 commits.

  • git commit：只是把代码保存在了您这台电脑的 Git 硬盘库里。

  Analyzing the Code Logic
  这是一个非常经典的量化指标现象！胜率是 0% 但年化收益率有 19.15%，原因在于这两个指标在量化计算逻辑上的定义差异：
  ──────
  ### 1. 为什么“胜率”是 0.0%？

  • 胜率的量化定义：在量化交易统计中，胜率（Win Rate）专门统计的是已经完成卖出平仓（Closed Trades）的交易中，盈利笔数的占比。

           卖 出 平 仓 盈 利 笔 数
    胜 率  = ──────────────── × 100%
           已 卖 出 平 仓 总 笔 数

  • 当前实例状态：
      • 该实例创建于 2026-08-20（刚运行了 1~2 天）。
      • 目前持仓为 5 只，这 5 只标的全都是正在持有的未平仓头寸（Active Positions）。
      • 截至目前，系统尚未触发任何一次卖出平仓交易（已平仓笔数为 0）。在已平仓笔数为 0 的情况下，浮盈不计入已结胜率，因此系统默认显示胜率为 0.0%。
      • 后续变化：当未来发生股票/债券触发止盈或调仓卖出后，胜率就会根据卖出平仓的实际盈利笔数实时更新。

  ──────
  ### 2. 为什么“年化收益率”会有 19.15%？

  • 累计收益率：当前实例的实际浮动收益为 +0.14%（初始资金 100,000 元变为了 100,144.09 元，浮盈 144.09 元）。
  • 年化收益率的复利折算公式：

                                   365
                                 ────────
                                 运 行 天 数
    年 化 收 益 率  = (1 + 累 计 收 益 率 )         - 1

  • 时间放大效应：
      • 实例刚创建运行了不到 2.7 天。
      • 根据复利公式，如果把 2.7 天内获得的 +0.14% 收益按一年 365 天的年化复利进行折算：


                365
                ───
                2.7
    (1 + 0.0014)    - 1 ≈ 19.15%

  • 也就是说，年化收益率较高是因为建仓运行天数极短（分子基数小被年化公式放大）。
  ──────
  ### 💡 总结与建议

  • 胜率 0.0%：是因为尚无已卖出平仓记录（5 只标的均在持仓浮盈中）。
  • 年化 19.15%：是因为运行天数短导致的时间放大现象（实际累计收益为 +0.14%）。

  当该持仓实例运行 1~2 个月、并产生多笔卖出平仓交割单后，胜率和年化收益率都会逐渐收敛并展示出长期稳定的真实水平！
